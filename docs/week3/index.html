What I learned

Describe your design: why these routers, LANs and links, and how you chose the addresses.

I designed a network with four routers (r1, r2, r3 and r4) and four LANs, each containing one host. The routers are connected in a ring topology, providing an alternative physical path between routers if a link fails. I used the IPv4 block 10.58.0.0/16 based on the last two digits of my student ID. Each LAN uses a separate /24 subnet, while the router-to-router links use /30 subnets. This keeps the networks separate and provides enough usable addresses for each connection.

Which route summarises several LANs? Which networks does it cover, why is it correct, and what else would it attract if you added a network inside its range?

I used the summary route 10.58.20.0/23 to combine two LANs: 10.58.20.0/24 (h2) and 10.58.21.0/24 (h3). On r1, the summary route forwards packets through 10.58.100.2 (r2), while r4 forwards matching traffic through 10.58.102.1 (r3). This reduces the number of routing entries because one route covers both LANs. The /23 prefix covers addresses from 10.58.20.0 to 10.58.21.255. Any additional subnet inside this range would also match the summary route. However, a more specific matching route would take priority because routers use longest-prefix matching.

When you took a link down, what happened, and why couldn't your routes recover even though another path existed? What would have recovered?

When I took down the link between r1 and r2, communication from h1 to h3 failed. The traceroute stopped at 10.58.10.1 (r1) and displayed !N, indicating that the destination network was unreachable. This happened because r1's summary route 10.58.20.0/23 depended on the next hop 10.58.100.2 (r2), which was no longer reachable through the failed link. Although an alternative physical path through r4 and r3 still existed, the static routing configuration did not provide automatic failover. A dynamic routing protocol such as OSPF could detect the topology change and recalculate an alternative route to restore connectivity.

In your network, what was the control plane? Who worked out the routes, and what does that mean for a network of 40 routers?

In my network, I acted as the control plane by designing the static routes in network.yaml. The Python script checked the network using check_spec() and check_paths() before applying the routes to the Linux routers. The routers then used their forwarding tables to decide where to send packets. In a larger network with 40 routers, manually maintaining static routes would be more difficult and could introduce errors such as routing loops or unreachable destinations. A dynamic routing protocol such as OSPF could automatically exchange routing information and recalculate paths when network connectivity changes.
